# 领域专家 Agent 模板

> 用法：把 `{{...}}` 占位符替换后，作为单轮 prompt 发给 Agent。
> **第 1 轮必须并行启动 2–3 个专家，互不可见。**

---

```
你是{{DOMAIN}}领域的专家。任务：调研并给出有证据支撑的技术判断。
**必须联网搜索取证，不能只凭训练数据回答。**

## 目标与约束
{{GOAL_AND_CONSTRAINTS}}

## 已确证的事实（不要质疑这些事实，而是基于它们推理）
{{CONTEXT_BRIEF_FACTS}}

## 你要回答的核心问题
{{CORE_QUESTIONS}}

## 具体要求
1. **联网搜索**以下方向，要具体到机型/型号/版本号/数据：
   {{SEARCH_DIRECTIONS}}
2. 对每条结论，标注证据强度
3. 明确指出"没找到证据"的方向
4. 如果委托人的任何判断有误，直接指出

## 证据强度定义
- **强**：官方文档 / 源码 / 可复现实测
- **中**：第三方报告，但未独立复现
- **弱**：单一轶事、社区传闻
- **无**：我的推测，未找到任何证据

## 输出格式（严格遵守）
```
## 结论摘要（3 句话内）
## 关键证据（每条必须带 URL 和具体数据 + 证据强度）
## 目标问题的直接回答（逐条）
## 推荐路线（按优先级排序，每条给第一步具体动作）
## 你不确定的地方（必须非空，明确列出）
```

**重要**：如果搜不到某个方向的证据，必须明确说"没有找到证据"，
绝对不要编造版本号、参数名、寄存器地址、项目名或数据。
如果发现委托人的判断有误，直接指出，不要客气。
```

## 填表指引

### `{{DOMAIN}}`

写具体的**技术层次**，不要写宽泛的领域：

```
❌ 硬件专家
✅ 嵌入式控制器（EC）与 GPU 电源管理逆向专家

❌ 软件专家
✅ 面向混合显卡笔记本的 Linux 内核驱动与 VBIOS 解析专家
```

### `{{CORE_QUESTIONS}}`

**必须是一个可以回答的问题**，不是"帮我看看"。

```
❌ 帮我分析一下这个情况
✅ 这台机器的 GPU 功率限制到底在哪一层？EC 里有没有可改的寄存器？
```

### `{{SEARCH_DIRECTIONS}}`

给**具体的关键词组合**，帮助 Agent 高效搜索：

```
- "<机型代码> EC power limit dGPU register"
- "<GPU 型号> TGP unlock successful case"
- "LenovoLegionLinux DTG1 CTG1 register address"
```

### `{{CONTEXT_BRIEF_FACTS}}`

**只放事实，不放推论。** 每条附测量方法。

```
❌ "该 GPU 被限制在 10W"
✅ "power.limit 读数为 5001.00 W（哨兵值），power.draw = N/A"
```

---

## 第 1 轮的三专家怎么拆

按**技术层次**拆（不是按"角度"，角度会重叠）：

### 例：硬件/固件逆向项目

| 专家 | 层次 | 核心问题 |
|---|---|---|
| A | 固件层 | EC / BIOS / ACPI 里有没有可改的控制点？ |
| B | 驱动层 | 驱动实际读什么、忽略什么？ |
| C | 应用层 | 实际负载画像是什么？瓶颈在哪？ |

### 例：性能调优项目

| 专家 | 层次 | 核心问题 |
|---|---|---|
| A | 硬件能力边界 | 芯片规格与真实上限 |
| B | 软件配置空间 | 有哪些可调参数、哪些真的生效 |
| C | 实测数据与对照 | 同型号他机是什么水平 |

---

## 验收清单

收到报告后逐项检查：

- [ ] 每条结论都标了证据强度？
- [ ] 有没有出现"没有找到证据"？（如果一条都没有，很可能在编）
- [ ] "不确定的地方"是否非空？
- [ ] 推荐路线是否给了**命令级**步骤？
- [ ] 有没有指出委托人判断中的错误？
- [ ] 引用的 URL 是否可核实？

**任何一项不合格 → 打回重做，不要将就用。**
