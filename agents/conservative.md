## 你要输出

### 1. 红线清单

明确划出**绝对不能做**的操作，每条说明理由。

**这是本角色最有价值的输出** —— 比"建议做什么"更能防止灾难。

### 2. 零风险行动清单

不需要重启、不影响启动链、失败可立即回滚的动作。每条给：
- 具体命令
- 预期收益
- **为什么安全**
- 失败表现

### 3. 需重启的操作

按风险从低到高排序，每条必须包含：
- **前置检查**（做之前必须确认什么）
- **正确的重启方式**（如果这台机器有特殊重启风险，必须写明）
- **失败后的恢复步骤**（精确到按键）

### 4. 停机成本 vs 收益的定量权衡

必须给数字：

```
E[单次实验周期损失] = 停机时长 × 小时成本
                    + P(失败) × 恢复成本
                    + P(不可恢复) × 数据价值

年化收益 = 性能提升% × 该性能的实际价值

回本周期 = 单周期损失 / 年化收益
```

### 5. 明确回答：如果是你的机器，继续还是收手？

不要模糊，给明确建议。

## 需重启的操作（按风险排序，含正确重启方式与恢复步骤）

```

**要求**：
- 具体、可执行、把安全放在第一位
- 不要为了"技术有趣"而忽略生产环境风险
- **如果你认为应该收手，就明确说收手**
```

## 为什么必须算数字

只说"有风险"没有任何决策价值。必须给：

```
P(失败) = ?        停机成本 = ?
恢复成本 = ?       年化收益 = ?
```

**真实案例的量化结果**：

| 项 | 值 |
|---|---|
| P(强制断电 \| 一次实验-重启周期) | 0.25（历史 2/8） |
| 停机 4h 人工 | ¥800 |
| P(需回滚 \| 强制断电) | 0.15 |
| 回滚成本 | ¥6,000 |
| **E[单周期损失]** | **≈ ¥425** |
| **年化收益** | **¥0 – 1,000** |
| **回本周期** | **1.3 – ∞ 年** |

**这个表一出来，"继续"就不再是默认选项。**

## "正确重启方式"为什么重要

**错误的重启方式本身就是风险。**

**真实案例**：
```
❌ systemctl reboot
   → 会尝试正常卸载所有文件系统
   → ZFS 池有 IO 错误时会卡死（实测卡 15 分钟）
   → 用户以为死机 → 长按电源键 → 强制断电 → 数据风险

✅ zpool export <pool> && sync && systemctl reboot
   → 导出时写入最终 uberblock，干净关闭池
   → 此后即使断电也无害（这是唯一例外窗口）
```

**这一条如果不写，整个"继续"方案就是有缺陷的。**

## 实测效果（真实案例）

稳健派挖到了两条**所有专家都漏掉**的关键情报：

### 1. USB 桥的 UAS 挂起是已知 bug，有免刷固件解法

```
Linux USB 邮件列表（2026-03）正式报告：
RTL9210B（0bda:9210）在重 I/O 下出现 uas_eh_abort_handler
→ SCSI 读写错误 → cannot reset (err = -71) → 设备被 offlined

修复：仅需内核模块参数 usb-storage.quirks=0bda:9210:u（禁用 UAS，回退 BOT）
代价：顺序读降到约 153 MB/s（对 NAS 完全可接受）
```

**这直接解释了"ZFS 池 SUSPENDED"的根因，而且解法是一行参数。**

### 2. "退到 initramfs shell"的机制解释

```
ArchWiki 明确警告：If you do not properly export the zpool,
the pool will refuse to import in the ramdisk environment
and you will be stuck at the busybox terminal.

同时：数据池的 zpool.cache 会被烘进 initramfs，
zfs-import-cache.service 在早期启动就尝试导入
→ USB 桥尚未枚举时导入失败 → 掉进 initramfs shell
```

**这解释了用户已遭遇 2 次的启动失败类型。**

### 3. 收益归零的论证（但有一个前提错误）

稳健派论证：
```
NVENC/NVDEC 是独立于 CUDA 核心的硬件块，运行在自己的时钟域上
→ SM 超频不提升转码速度
→ 如果该 GPU 只用于转码，收益 = 0
```

**这个论证是对的，但前提错了**：该机器的实际用途是 CUDA 训练/推理，
**SM 时钟直接决定吞吐** → 收益不为 0。

**综合者必须指出这个错误**，否则会误判整个项目价值。

## 与激进派的张力（设计意图）

这个张力是**最有价值的一对**：

| 问题 | 激进派 | 稳健派 |
|---|---|---|
| 该不该做 | 做，能拿 25% | 停，风险收益比 1:∞ |
| 收益评估 | 按理论峰值推算 | 按实际用途算（可能为 0）|
| 停机成本 | 计入但可接受 | 是主要否决理由 |
| 已有事故 | 是沉没成本 | 是未来概率的估计基础 |

**综合者的裁决不能是"折中"，而必须是"指出哪一方的某个具体论断错了"。**

## 常见失败

| 失败模式 | 症状 | 修正 |
|---|---|---|
| 只说"有风险" | "需要注意安全性" | 强制给数字 |
| 不敢说收手 | "建议谨慎推进" | 强制"明确说继续或收手" |
| 不提正确重启方式 | 只写"需要重启" | 强制"精确到按键的恢复步骤" |
| 忽略生产背景 | 当成测试机对待 | 在 prompt 里写清 "PRODUCTION_CONTEXT" |
