# 工作流详解

## 阶段 0：判断是否需要用这个框架

**用之前先问**：这个决策符合以下几条？

- [ ] 有多条互斥路径，需要排序
- [ ] 失败代价大（生产环境 / 不可逆操作 / 数据风险）
- [ ] 我自己已经有初步倾向（**越是有倾向，越需要红队**）
- [ ] 决策会消耗数小时以上

**如果只符合 0–1 条 → 直接做，不要用框架。**

---

## 阶段 1：编写 Context Brief（关键，占 30% 价值）

用 `templates/context-brief.md`。

### 铁律

#### 1. 只写事实，不写推论

```markdown
❌ "该 GPU 的功率被 EC 限制在 10W"
✅ "power.limit 读数为 5001.00 W（哨兵值）；power.draw = N/A"
```

#### 2. 每个事实必须附测量方法

```markdown
❌ "负载时钟 1290-1346 MHz"
✅ "负载时钟 1290–1346 MHz（fp32 GEMM 2048²，nvidia-smi 每 0.4s 采样，
    15s 稳态，温度自 65°C 升至 77°C）"
```

#### 3. 已排除的路径必须写"否证方法"

```markdown
## 已排除路径
- ACPI 改 TGPV：把 Name(TGPV, 0x2710) 运行时改为 0x3A98（+50%），
  GPS 接口读回确认修改生效，但控温 A/B 4 轮性能差异 -0.09%
  → 结论：Linux 驱动不读该值
```

#### 4. 列出"我不知道什么"

这一节比"我知道什么"更重要。

```markdown
## 未知
- 实际功耗（功率计未测）
- 该机是否支持 Dynamic Boost（未查 /proc/driver/nvidia/gpus/*/power）
- CPU 侧负载对 GPU 时钟的影响（未测）
```

## 阶段 2：第 1 轮 —— 三专家并行

### 选角色

按**技术层次**拆分，不要按"角度"拆分（角度会重叠，层次不会）：

```
例（硬件逆向）：
  专家 A = 固件层（EC / BIOS / ACPI）
  专家 B = 驱动层（内核模块 / VBIOS 解析）
  专家 C = 应用层（性能调优 / 散热 / 实际负载画像）
```

### 并行启动

**必须同时启动**（同一批次），确保互不可见。

### 统一输出格式

每个专家必须按这个结构输出：

```markdown
## 结论摘要（3 句话内）
## 关键证据（每条带来源 + 证据强度 强/中/弱/无）
## 目标问题的直接回答（逐条）
## 推荐路线（按优先级，每条给第一步具体动作）
## 你不确定的地方（必须非空）
```

### 验收标准

| 检查项 | 不合格表现 |
|---|---|
| 有没有标注证据强度 | 全部标"强"或全部不标 |
| 有没有说"没找到证据" | 全部都有结论（说明在编） |
| 不确定清单非空 | 空的 → 要么在装懂，要么没深入 |
| 有没有给命令级步骤 | 只有"建议使用 X 工具" |

## 阶段 3：第 2 轮 —— 红队 + 双决策（三路并行）

### 输入

把**第 1 轮全部输出**（三份完整报告）+ **Context Brief** 一起喂进去。

### 红队（`agents/red-team.md`）

**核心要求**：它的 KPI 是找到错误数量。

必答四问：
1. 哪些是事实、哪些是被当作事实的推测？
2. 三份报告之间哪里互相矛盾？谁更可能对？
3. 委托人的实测结论有没有**其他解释**？
4. 三份报告**共同遗漏**了什么？

**最有价值的一问是第 4 问。** 真实案例中，红队靠这一问挖出了：
- `nvidia-powerd` / `/proc/driver/nvidia/gpus/*/power`（全都没提）
- 适配器识别可能影响功率预算（全都没提）
- `clock64()` 微基准量真实时钟（全都没提）

### 激进派（`agents/aggressive.md`）

**禁止**用"风险大"作为不做的理由。

必答：
- 天花板在哪一层？（含证据链）
- 按"预期收益 × 成功概率 / 成本"排序的行动清单
- 如果所有手段用尽，最终能达到多少？（给区间 + 置信度）

### 稳健派（`agents/conservative.md`）

**核心 KPI 不是性能，是"不把生产环境搞挂"。**

必答：
- 红线清单（绝对不做，含理由）
- 零风险行动清单
- **停机成本 vs 性能收益的定量权衡**
- 明确回答"如果是你的机器，继续还是收手"

## 阶段 4：综合裁决（你自己做）

用 `templates/decision-record.md`。

### 必须做的三件事

#### 1. 指出各方的事实错误

**每方至少一条。** 如果找不出来，说明你没认真读。

真实案例：
```markdown
- 稳健派错误：假设该 GPU 只用于视频转码，据此论证"优化收益为 0"。
  但实际用途是 CUDA 训练/推理，SM 时钟直接决定吞吐 → 收益不为 0。
- 激进派错误：把 "CTGP=0 解释 5001W" 当作结论，
  但实测改 CTGP 后 power limit 仍是 5001 → 假设被否证。
- 红队错误：未验证 "5001 = 显存时钟巧合" 这个猜测，
  只是提出了另一种可能，却未标注为【假设】。
```

#### 2. 分档执行计划

```
第 0 档：零重启零风险，先做（信息价值最高）
第 1 档：一次重启，可能拿回大头
第 2 档：零重启，边际收益
第 3 档：高风险，仅在前三档成功后考虑
```

**每档必须写：做什么、预期收益、验证方法、失败后果。**

#### 3. 停止线

```
如果 <实验 X> 证明 <命题 Y> 不成立
→ 接受 <Z> 为最终值，不再投入。
```

---

## 阶段 5：执行与回填

每档执行完，回填决策记录：

```markdown
### 第 0 档执行记录
- 实验：`nvidia-smi -lgc 300,900`
- 结果：频率未变（仍 1346）
- 判读：锁被屏蔽
- 对决策的影响：跳过第 2 档的锁频路线，直奔第 1 档
```

**这份记录是下一次决策的输入**，比任何总结都有价值。

## 反模式：什么时候这个流程会失败

| 失败模式 | 症状 | 修正 |
|---|---|---|
| Context Brief 里塞了倾向 | 三份报告结论一致 | 重写 Brief，删掉所有"我认为" |
| 专家任务重叠 | 三份报告 60% 内容重复 | 按技术层次重新拆分 |
| 红队被 prompt 驯化 | 报告全是"同意，补充……" | 在 prompt 里加入"可以指出委托人错误" |
| 综合裁决和稀泥 | 输出"各方都有道理" | 强制要求"每方至少一条错误" |
| 忘记停止线 | 无限试下一个方案 | 决策记录模板里停止线是**必填项** |

## 时间预算参考

| 阶段 | 耗时 |
|---|---|
| Brief 编写 | 20–40 min |
| 第 1 轮（3 专家并行） | 10–20 min（等待） |
| 第 2 轮（3 角色并行） | 10–20 min |
| 综合裁决 | 20–30 min |
| **合计** | **约 1–2 小时** |

**这个投入只有在"决策错误代价 > 2 小时"时才值得。**
