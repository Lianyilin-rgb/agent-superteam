## 为什么用 ADR 风格

| 好处 | 说明 |
|---|---|
| **可追溯** | 半年后能看懂当时为什么这么决定 |
| **可复用** | 下次遇到类似问题，直接查历史决策 |
| **强制结构化** | 填不满模板说明想得不够清楚 |
| **保留冲突** | 各方的分歧是宝贵信息，不应被抹平 |

---

## 填写要点

### 第 5 节"各方的错误"是必填

**这是 ADR 最核心的一节。** 它证明了"这不是一个和稀泥的决策"。

如果某一方确实没错，写"未发现错误，检查了以下方面：……"。

### 第 6 节"停止线"必须具体

```markdown
❌ "如果效果不好就停止"
✅ "如果 `-lgc 300,900` 后频率仍为 1346，
    且开 GSP 后 Target Temp 仍为 N/A
    → 接受 2.09 TFLOPS 为天花板，不再投入"
```

### 第 7 节必须在执行后回填

**没回填的 ADR 只有一半价值。**

回填时要写"对决策的影响" —— 这是最有价值的部分：

```markdown
- 结果：`-lgc 300,900` 后频率仍 1346（未掉下去）
- 判读：锁被驱动/VBIOS 屏蔽
- 对决策的影响：跳过第 2 档的锁频路线，直奔第 1 档（开 GSP）
```

## 真实案例（节选）

```markdown
# ADR-001: MX450 算力提升路径决策

- 日期：2026-10-24
- 状态：已采纳，第 0 档执行中
- 参与角色：专家×3、红队、激进派、稳健派

## 背景
生产 NAS 上的 MX450 在 Linux 下只能跑 2.09 TFLOPS，
低于同芯片他机 16-18%，需要确定瓶颈层与投入上限。

## 关键事实
| 事实 | 方法 | 数值 |
|---|---|---|
| 空闲时钟 | nvidia-smi | 1395 MHz / P0 |
| 负载时钟 | GEMM 2048² 15s | 1290–1346 MHz |
| 功率限制 | nvidia-smi -q -d POWER | 5001.00 W（哨兵） |
| 温度阈值 | nvidia-smi -q -d TEMPERATURE | **N/A** |
| 支持时钟 | --query-supported-clocks | 388 档，最高 2100 |

## 各方意见
- 激进派：开 GSP 修 Target Temp，可能一次拿回 16-18%，预测 +6~25%
- 稳健派：收手，风险收益比 1:∞
- 红队：指出 -lgc 实验设计缺陷 + 5001 数值巧合未验证

## 裁决
### 各方的错误
- 稳健派：假设 GPU 只用于转码→收益为 0，但实际是 CUDA 计算，SM 时钟直接决定吞吐
- 激进派：把 "CTGP=0 解释 5001W" 当结论，但实测改 CTGP 后仍是 5001
- 红队：指出 5001 巧合后未标注是假设还是已验证

### 采纳
分三档：第 0 档诊断（零风险）→ 第 1 档开 GSP + USB quirk（一次重启）
→ 第 2 档 NVML 降压（零重启）

## 停止线
若 `-lgc 300,900` 无效 且 开 GSP 后 Target Temp 仍 N/A
→ 接受 2.09 TFLOPS，收手
```
