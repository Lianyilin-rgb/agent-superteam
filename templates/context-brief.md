## 填写要点

### 事实必须可复现

```markdown
❌ "负载时钟约 1300 MHz"
✅ "负载时钟 1290–1346 MHz
    （fp32 GEMM 2048²，nvidia-smi 每 0.4s 采样，15s 稳态，
      温度自 65°C 升至 77°C，共 34 个采样点，均值 1318）"
```

### 已排除路径必须写方法

```markdown
❌ "ACPI 改功率值无效"

✅ "ACPI 改 TGPV：
    把 SSDT16 里的 Name(TGPV, 0x2710) 用内核模块运行时改为 0x3A98（+50%），
    用 acpi_call 调 GPS(0x0100, 0x2A) 读回确认 PCGP 已变为 0x3A98，
    然后做控温 A/B 交替测试（每轮等温度降到 63°C 起跑，各 15s GEMM）：
      A(15000): 2.0688 / 2.0657  TFLOPS
      B(10000): 2.0687 / 2.0696  TFLOPS
    → 差异 -0.09%，判定驱动不读该值"
```

**没有方法的"已排除"是耍流氓**，下一轮会被红队打回。

### 未知清单必须具体

```markdown
❌ "还有一些不确定的地方"

✅ "未知：
    - 实际功耗（无功率计，nvidia-smi 读数为 N/A）
    - 该机是否支持 Dynamic Boost（未查 /proc/driver/nvidia/gpus/*/power）
    - CPU 侧负载对 GPU 时钟的影响（未做 CPU 满载对照）
    - 空闲时钟 1395 是否真是实时值（未用 clock64() 微基准交叉验证）"
```

## 反模式

| 反模式 | 症状 | 后果 |
|---|---|---|
| **塞入倾向** | "我认为问题在 X，请验证" | 三份报告结论趋同，交叉失效 |
| **推论当事实** | "该 GPU 被限制在 10W" | 下游基于错误前提推理 |
| **缺测量方法** | 只写数值不写怎么来的 | 无法判断可信度，也无法复现 |
| **未知留空** | 只列"我知道的" | 盲区永远不会被发现 |
| **忽略非技术因素** | 只写技术环境 | 稳健派无法算账 |

## 真实案例（节选）

```markdown
## 目标
提升 <设备> 上 <GPU> 的可用算力（当前 fp32 GEMM 天花板 2.09 TFLOPS）

## 硬约束
- 绝不物理拆机（设备为唯一生产机，拆机风险 > 收益）

## 环境
- 系统：fnOS (Debian 12 base)
- 内核：6.18.18.c1126-trim
- 驱动：NVIDIA 580.142 闭源模块，NVreg_EnableGpuFirmware=0（GSP 关闭）
- 硬件：<CPU> + <GPU>，65W 适配器，单风扇，GPU/CPU 共享热管

## 已确证的事实
### 时钟
事实：空闲 clocks.sm=1395 MHz，P-state=P0
方法：nvidia-smi --query-gpu=clocks.sm,pstate --format=csv
条件：无负载，温度 58-60°C

事实：负载 clocks.sm 1290–1346 MHz
方法：fp32 GEMM 2048²，0.4s 采样 × 15s 稳态，34 点
条件：温度 65→77°C

### 功率
事实：Current/Default/Max Power Limit 全为 5001.00 W；power.draw = N/A
方法：nvidia-smi -q -d POWER
条件：任意负载

## 已排除的路径
| 路径 | 否证方法 | 结果 |
|---|---|---|
| ACPI 改 TGPV | 运行时改 +50% + 控温 A/B 4 轮 | -0.09%，无效 |
| ACPI 改 CTGP | 0→1，观察 power limit | 仍 5001，无效 |

## 已知隐患
- ZFS 池曾有 SUSPENDED，5 个永久元数据错误
- systemctl reboot 会卡在卸载 ZFS 池（实测 15 分钟）
- 历史：2 次启动失败，2 次强制断电

## 待决策问题
1. 时钟瓶颈在硬件层还是配置层？
2. 在"绝不拆机 + 生产环境"约束下，值得投入多少？

## 我不知道什么
- 实际功耗（无功率计）
- 是否支持 Dynamic Boost（未查）
- CPU 负载对 GPU 时钟的影响（未测）
```
